# Taste Profile
- Works on Windows with PowerShell (Windows-style paths like `C:\Users\...`, commands like `Measure-Object -Line`); keep shell commands PowerShell-compatible, not bash. Confidence: 0.8
- When reporting bugs, expects a full-workflow deep analysis with root-cause fixes across the entire flow ("analyse the full work flow... dont leave anything analyse everything") — not spot patches on only the mentioned symptoms. Confidence: 0.85
- Grants broad autonomy on large fixes ("i trust u more") — wants multi-file overhauls carried end-to-end in one pass ("make the whole thing in one flow"), analyze → fix → verify, without pausing for approval. Confidence: 0.85
- Expects "error free" claims to be backed by verification (typecheck, lint, production build) before declaring work done. Confidence: 0.8
- Bug reports arrive vague and casual (e.g. "date managements", "status updates sycning", "big mess in the data selections") — expects the agent to autonomously diagnose the precise root causes rather than ask clarifying questions first. Confidence: 0.75
- Forms must be scoped to the exact entity being edited: on multi-entity records (a PO with several product lines), surface an explicit selector, derive every field/default/validation from the selected entity — never hardcode the first one — and scope the store mutation to that entity. Defaulting the selection to the least-progressed (bottleneck) entity is the desired behavior. Confidence: 0.8
- Derived state (e.g. milestone progress computed from material receipts) must be re-synced after EVERY mutation path via one shared, idempotent helper so all flows converge — stale derived data ("received date is not proper yet") is treated as a bug by the user, not an accepted eventual-consistency gap. Confidence: 0.8
- Use `—` (em dash) as the empty-value placeholder in tables; fix mojibake/corrupted characters (�) wherever they turn up instead of leaving them. Confidence: 0.6
- For this project, "start the server" means run `npm run dev` (Vite dev server, port 5173) in the background, then verify it's actually serving with an HTTP check (curl localhost:5173, plus the /api/shared-state endpoint) — piped Vite log output can be empty, so never rely on logs to confirm startup. Confidence: 0.6
- Persisted data must self-heal on load: a load-time normalizer should sanitize impossible stored values (e.g. actual/received dates in the future) rather than letting validation fail on data the user can't even see; and form date fields need explicit set/clear semantics ('' clears, undefined keeps) — never "empty means keep old", which traps stuck legacy values the user cannot fix through the UI. Confidence: 0.7
- Wants fast, token-efficient operation: minimal narration/progress chatter, targeted greps and scoped edits instead of full-file reads or long explanations, and quick resumption of pending work without verbose status recaps ("do them quickly and then use efficient tokens"). Confidence: 0.85
